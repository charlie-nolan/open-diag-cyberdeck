# ADR-0003: Subaru SSM2 over K-line and the OBDLink EX (app/ssm/)

Status: Accepted (recorded 2026-11-20)

## Context

These decisions were written as code comments next to the code they explain. Comments are banned
(ADR-0001), so they are kept here. Each entry names the file and the function or class it applies to;
search the file for that name. When the code changes, update or remove the entry in the same change.

## Decisions

### `app/ssm/ex_ssm2_probe.py`

- `STNSSM2.cmd`: True: STN adds nothing, we build the whole SSM2 frame.
- `STNSSM2.open`: App copy: exclusive, so nothing else shares the port (pyserial >= 3.3)
- `STNSSM2.setup`: ATAT0: fixed STPTO wait, slow 4800-baud replies.
- `STNSSM2.setup`: No STN checksum: our frame already carries one.
- `STNSSM2._parse`: STN may or may not print the checksum byte; check it if it is there.
- Raw: ISO 9141 preset with no header and no checksum, so the STN sends our complete SSM2 frame byte for byte (sidesteps the ELM length-byte problem).
- `main`: Generic OBD-II identity first (read-only Mode 01/09 requests): which protocol answers, which OBD standard the ECU claims, and whatever Mode 09 it supports (VIN 02, calibration ID 04, CVN 06, ECU name 0A). Mode 09 is optional before MY2005.

### `app/ssm/ssm2_capabilities.py`

- `ECUCaps.bit`: FreeSSM tables use 1-based flag byte and bit numbers.
- `ECUCaps.bit0`: FreeSSM interface code uses 0-based (byteindex, bitnr)
- `read_dtcs`: The init reply advertises no DTC blocks: that is "nothing to read", not a failed read.

### `app/ssm/ssm_tests.py`

- FreeSSM: some ECUs don't report 0 with the engine off.
- FreeSSM writeAddress_permanent delay.
- `Refused`: Repeat writes in a row with no answer before the test is called off.
- `SubaruTests._check_test_mode`: FreeSSM: the ECU would advertise the test-mode switch if it mattered.
- `open_subaru`: The first try after plugging in often gets no answer.

### `app/ssm/telemetry_logger.py`

- Reads: 0xBF = ECU init identify, 0xA8 = read single addresses, 0xA0 = read a memory block. send_ssm2_command() refuses everything else. The only writes (0xB8, TEST MODE) go through ssm_tests.py, which checks each one against the tests this ECU advertises.
- `TelemetryPoller._init_db_wal`: Only the logger needs the session DB. A one-off read (READ CAR) must not fail because the checkout is missing or read-only, so this runs when polling starts, not in __init__.
- `TelemetryPoller.connect_serial`: Exclusive: a second program (or a second deck thread) can't share the K-line.
- `TelemetryPoller._transact`: K-line is half duplex: the cable echoes what we sent. The echo takes as long as the packet takes on the wire (103 bytes = 215 ms at 4800 baud), so the timeout scales with it.
- `TelemetryPoller._transact`: Find the reply header, skipping up to 8 stray bytes (K-line glitches at key-on).
