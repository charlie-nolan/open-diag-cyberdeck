# ADR-0005: App checks, OBD-II, telemetry and voice (app/)

Status: Accepted (recorded 2026-11-20)

## Context

These decisions were written as code comments next to the code they explain. Comments are banned
(ADR-0001), so they are kept here. Each entry names the file and the function or class it applies to;
search the file for that name. When the code changes, update or remove the entry in the same change.

## Decisions

### `app/answer_check.py`

- Words that describe a fault or a job, not a part: never the word that decides whether the manual names a part.
- `check`: A part is "never named" only when one of its specific words is on no page of this car's manual: long descriptive names ("FL ABS sensor connector/harness disturbed") never match as a whole.

### `app/car_records.py`

- `values`: A records problem must never stop a read.

### `app/common_issues.py`

- Which part of the car a forum thread is about, from the words in its title (vocabulary only: says nothing about causes). A title can count for more than one system.
- `gather`: Widen to neighbouring years only when one year has too few reports.

### `app/faithfulness.py`

- Unit -> (group, factor to the group's base unit). Groups keep "25 N·m" from matching "25 mm" on the same page. (?i:...) where the manuals vary the case ('29 ft. lbs.', '22 Ft. LBS.'); single letters (V, A, L, h) stay exact.
- Part numbers in any maker's style: 6+ characters of letters/digits/dashes with 3+ digits ('13028AA21C', 'F7AZ-9H307-AB', '90919-01253', '19115080'). Codes and years are not part numbers.

### `app/live_data.py`

- Generic ranges (gasoline engines, common OBD-II practice, not any one car). explain() judges with these, and kb/build_telemetry.py stores the same numbers as the 'generic' telemetry zones: change them here only.
- The unit every value is judged in. A reading in another unit of the same quantity is converted (mph, °F, psi, mV); a unit of another quantity drops the reading. No unit after the number means this unit.

### `app/obd_all.py`

- Waits only while the adapter is silent; a normal reply returns at once.
- Quick failures first; K-line bus inits take seconds.
- `_o2`: PID 4F changed the full scale of these: the fixed formula would be wrong.
- `read_all`: K-line and busy CAN buses miss the odd request; a bitmap PID should answer.
- `mode06`: Python-obd drops multi-frame service 06 replies.

### `app/procedures.py`

- `parse`: First, so the prompt always says they are unverified.
- `path_from_scan`: A run starts at an answered step that no other answered step can lead to (either branch)
- `render`: Still too long: the scan path and where it lands in full, everything else as its title only, then shorter titles, then only the other steps' numbers. The steps in keep are never the ones that get cut: cutting the whole text at the budget used to drop exactly the step the scan leads to (it's often last).

### `app/retrieval.py`

- `Retriever.specs`: Only rows parsed from the FSM's own tables. The hand-entered rows are Gemini's fabricated "hand-verified" specs and the JIS rows are generic bolt charts, not Subaru values: a wrong torque label is still a wrong torque, so neither is shown or fed to the model.

### `app/sanity_check.py`

- Generic physical limits: what a road vehicle's signal can physically read, not what is healthy, never a cause. key: (low, high, unit, why)

### `app/telemetry_ref.py`

- Some adapters measure the connector voltage themselves (ELM/STN ATRV); that is a different measuring point from the ECU's own supply-voltage reading, so it gets its own key.
- SAE J1979 mode 01 scalar PIDs: pid -> (bytes, expression in A,B,C,D, unit). Every formula here is unit-tested against python-obd's decoder (kb/tests/test_telemetry.py).
- O2 voltage labels name the sensor's place, so a car whose PID 1D moves B2S1 to PID 16 still gets the right key.
- `normalize`: No definition: no number (never guess a scaling)

### `app/theme.py`

- Status word -> colour; always shown with the word too, never colour alone.

### `app/vehicle_id.py`

- Built-in World Manufacturer Identifiers (first 3 VIN chars). kb/vin.db, when present, covers every make.
- Subaru chassis code (VIN positions 4-5) -> model. BE/BH/BL/BP/BR/BS are Legacy or Outback: not guessed.
- `slug`: Position 10, 1980..2009 (+30 when position 7 is a letter)
- `vin_year`: From 2010 on, makers put a letter in position 7 for light vehicles.
- `build_rom_db`: ------------------------------------------------------------------ Subaru ECU id -> year and model Cars before ~2005 rarely give a VIN over any cable, but every Subaru ECU sends its 5-byte ECU id in the SSM init reply. RomRaider's community ECU definitions list, per ECU id, the car it was built for (year, model, market, transmission). build_rom_db() turns those XML files into kb/romid.db once on the PC; the deck only reads that small table.

### `app/verdict_steps.py`

- `score`: A new part can be the fault, a tested one rarely.
- `score`: The guess itself is not evidence: it needs the manual or more facts to lead.

### `app/voice.py`

- `_whisper`: The listener sits on the small cores; whisper gets every core so a note doesn't take a minute.
- `_resampler.cb`: 48000 -> 16000: average each 3 samples (also a crude low-pass)
- `speak`: Two quick asks: the newer answer replaces the older one instead of talking over it.
