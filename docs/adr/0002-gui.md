# ADR-0002: Home app (app/cyberdeck_gui.py, app/ui/): config, models, case, screens

Status: Accepted (recorded 2026-11-20)

## Context

These decisions were written as code comments next to the code they explain. Comments are banned
(ADR-0001), so they are kept here. Each entry names the file and the function or class it applies to;
search the file for that name. When the code changes, update or remove the entry in the same change.

## Decisions

### `app/ui/config.py`

- Backend "cli": a command-line AI tool you're signed into (Claude Code, Gemini CLI/agy, Codex CLI), no API key. The command as a list; "{prompt}" is replaced by the prompt, else the prompt goes to stdin. Examples in docs/SINGLE_CAR_LAPTOP.md. Optional per role: "cli_cmd_fast", "cli_cmd_deep", "cli_cmd_think".
- Backend "openai": any OpenAI-compatible server (LM Studio, llama.cpp, Jan, vLLM, OpenRouter, ...). Its key, if it needs one, is read from the environment variable named in openai_key_env, never stored here.
- Lists = first file that exists wins, so the Qwen3 exports take over from Qwen2.5 with no config edit.
- No Qwen2.5-7B fallback: that old export fails rkllm_init on runtime 1.3.1. Missing 4B = the fast model.
- Cyberdeck Home (--home, or CYBERDECK_HOME=1): the models run on the home PC's Ollama over Tailscale; the deck's own models take over whenever the PC can't be reached.
- 10-21: Qwen3.6 35B for chat, Qwen3-Next 80B instruct for verdict/repair, its thinking twin for THINK HARDER; Ollama swaps them in the PC's RAM as needed.
- FINAL DIAGNOSIS in two passes: evidence only, then the opinions (OPINION_FIELDS)
- FINAL DIAGNOSIS in short steps (app/verdict_steps.py). Off: sim v5 (blind) steps 25/25 vs.
- One prompt 30/32 on Qwen 80B. "auto" = on for local models (Ollama/RKLLM), off for Claude/OpenAI-style APIs and team mode.
- Vosk "hey deck" + whisper.cpp dictation; off automatically if not installed.
- Speaking speed, words per minute (espeak's own default of 175+ was too fast)
- Obdlink = OBDLink EX: OBD-II + VIN, then Subaru SSM over it | kkl = bare KKL fallback.
- Other programs per make, opened from Intake with the cable handed over, e.g. "Ford": {"name": "FORScan", "cmd": "wine '~/.wine/drive_c/Program Files (x86)/FORScan/FORScan.exe'"}.
- Vector search: "" = find Qwen3-Embedding-0.6B by itself (models/qwen3emb, then the.
- `load_config`: Half-written file: start on the defaults instead of not at all.
- `load_config`: Config value(s) first, then the defaults; a stale path in config.json falls through.
- `load_config`: The deep (and think) model not copied yet: use the fast one and say so, rather than fail on a missing file.
- `load_config`: Voice files: models/voice/ (README) or models/vosk/ + models/whisper/ (The user's PC). A path in config.json that doesn't exist must not switch voice off when the files are in the other layout.
- `save_config_key`: Never replace a file we couldn't read with a one-key file.
- `save_config_key`: A power cut leaves the old file or the new one, never half of one.

### `app/ui/context.py`

- `community_block`: Whole entries only: slicing the joined text cut a thread off mid-sentence. A header with nothing under it is dropped too.
- `case_context`: Likely causes only: the card's "manual procedure outline" was summarised from cut-off text.
- `case_context`: The codes' own names find the right manual page when the question's words don't ("explain deeper")
- `case_context`: A page about one of the case's own codes is already covered by its procedure above.
- Intake fields that hold opinions, not evidence: guesses, another shop's idea, earlier unconfirmed diagnoses. The blind first pass of FINAL DIAGNOSIS ("verdict_blind_first") leaves these out; pass 2 weighs them on the evidence. Decided by field, never by words in the text. (key, label for pass 2)
- Alphabetical: list order must not favor a repair.
- `repair_from_verdict`: The repair the verdict names first wins, not the one listed first here.

### `app/ui/session.py`

- `Session.case_summary`: The models misread raw numbers (12 C coolant became "overheating"); Python says what they mean.
- `Session.case_summary`: With the manual text and history it must still fit 4096 tokens.
- `Session.case_summary`: After the cut, so a long case never drops the drive.
- `Session.case_summary`: After the cut: what the mechanic said must never be the part that gets dropped.

### `app/ui/models.py`

- `ModelManager.__init__`: DECK ONLY switch (Home mode): skips the PC check and uses the deck's RKLLM models; remembered in config.
- `ModelManager._pc_model`: Qwen's settings for thinking mode: top_p 0.95, top_k 20, and a presence penalty, which Qwen advises against the endless "wait... but..." loops quantized thinking models fall into (11-01 saw them)
- `ModelManager._get`: Loading a model briefly needs about 1.5x its file in free RAM; short of that the deck swaps until it freezes, so the loaded ones go first (they reload in seconds)
- `ModelManager._get`: One 4B at a time (deep and think swap); swap all on small boards; a model that only loads in domain 0 shares it with nothing.
- `ModelManager._get`: 11-02: keep the 1.7B and one 4B loaded together. Only when RAM is still short after the other 4B went does the rest go too (short loads made the deck swap until it froze). Checked after the swap: before, the RAM the other 4B was about to free counted as used, so every switch reloaded everything.
- `ModelManager._get`: Maybe the NPU wouldn't hold both: try this one alone, once.
- `ModelManager._trial`: The child needs the RAM and NPU memory this process is holding.

### `app/ui/workers.py`

- `VinWorker`: Only a speed-up: the first real search loads them instead.
- `OBDWorker._ssm_note`: A missing cable or driver must never close the app.
- `OBDWorker._ssm_note`: Only Subaru ECUs answer the SSM init, so this alone says the make.
- `OBDWorker._read`: Newer Subaru ECUs keep the VIN; read with 0xA8 like everything else.
- `OBDWorker._read`: No VIN, or a Subaru VIN: ask for SSM through the same EX (more codes and live values on a Subaru).
- `OBDWorker._read`: It already got no SSM answer this run: don't spend the time again.
- `OBDWorker._read`: The EX itself works on this car, only SSM through it doesn't.
- `OBDWorker._seen_obd`: TELEMETRY: what this car answered, kept per device (cache/telemetry_seen.db) for telemetry_ref.capabilities(). Reads only what the connection already learned; never sends anything extra. A failure never stops a read.
- `DriveWorker.run`: One bad read (a bump, a loose plug) mustn't end the drive log.
- `TestWorker.__init__`: 10-19: Subaru tests and clears always go over the KKL cable (the EX got NO DATA over SSM); the EX is only for mode 04 on other cars. cables.py tells the two apart when both are plugged in.
- `TestWorker._connect`: Each job uses whichever cable answers: the KKL cable first for SSM, then the EX.
- `TestWorker._mode04`: Python-obd needs the port to itself.

### `app/cyberdeck_gui.py`

- `CyberdeckApp.__init__`: Scrolls only when the screen is below the minimum, never at 150% scaling.
- `CyberdeckApp.__init__`: Pressing MIC must not take the cursor out of the box the words are meant for.
- `CyberdeckApp.__init__`: The whole window scrolls when the screen is smaller than the layout's minimum (desktop scaled to 160% leaves ~1200x675 logical px), so nothing is ever placed off screen.
- `CyberdeckApp.act_deck_only`: Don't swap models under a running answer.
- `CyberdeckApp._busy`: A model crash would take the running test's repeat thread with it before the switch-off.
- `CyberdeckApp._run`: ~3 chars a token, rounded toward safe.
- `CyberdeckApp`: One case's fields: cleared by a new case, saved with each visit, restored by LOAD LAST CASE PAST VISITS. Anything Session.case_summary() reads must be here or in CAR_KEYS (kb/tests/test_gui_pure.py checks).
- `CyberdeckApp.closeEvent`: Letting Qt destroy a running thread aborts the whole app.
- `CyberdeckApp.closeEvent`: Closing would kill it, maybe in the middle of a job on the car.
- `CyberdeckApp.closeEvent`: A CONNECT can take ~16 s; never drop a running thread.
- `CyberdeckApp.closeEvent`: Freeing an RKLLM handle while rkllm_run is still using it on the worker thread can crash on exit.
- `main`: A crash inside the NPU runtime closes the app with no Python error; this leaves the stack of every thread.

### `app/ui/screens/intake.py`

- `CyberdeckApp._fill_years`: 10-19: every start is a fresh case; LOAD LAST CASE brings the old one back.
- `CyberdeckApp._apply_vin`: Nothing saved for this car yet: ask NHTSA (free) if there's internet; the answer is kept offline.
- `CyberdeckApp._apply_ident`: A VIN already on screen may be the previous car's (NEW CASE keeps the car): only one typed after this read gets tied to this ECU.
- `CyberdeckApp._apply_ident`: The definition's model name must match one the manuals use ('Forester', not 'Forester XT 5MT')

### `app/ui/screens/records.py`

- `CyberdeckApp._store_case`: "(pending)" "(history)" etc. stay with their code, so the models see the status the scan tool gave.
- `CyberdeckApp._rec_car`: ------------------------------------------------------------------ per-car record file (records/<VIN>.db) Every reading (READ CAR and test drive), the chat and each visit's case go into the car's own SQLite file. Until the car has a VIN or customer key they wait in the session (records_pending), then get filed.
- `CyberdeckApp.act_test_drive.ident`: READ CAR, TEST MODE and other programs see the cable is busy.
- `CyberdeckApp._drive_file_start`: Every 30 s the same note would bury the screen.

### `app/ui/screens/chat.py`

- `CyberdeckApp.act_chat`: Slash commands never write to the session DB; only /save and /savewild do, on purpose.
- `CyberdeckApp.act_chat`: Every turn is a fresh prompt: the case, manual text found for the case AND the question, and the last few exchanges. The model's own memory isn't used, so it never fills up and resets, and a vague follow-up ("explain deeper") can't pull in unrelated manual pages (it once answered about bumpers).
- `CyberdeckApp.act_chat.go`: The codes in the query pull in the manual's diagnostic procedure first; then only owner-confirmed fixes (11-01: manual-biased, plus verified fix threads; unchecked threads stay out of chat)
- `CyberdeckApp.act_chat.go`: 10-19 18:07Z: chat on the fast model, fed only manual text; config "chat_model": "deep" for the 4B.

### `app/ui/screens/maintenance.py`

- `CyberdeckApp.act_wildcard.done`: Runs on the deep model: the small one drifts into nonsense at high temperature.

### `app/ui/screens/verdict.py`

- `CyberdeckApp._verdict_view`: No Thinking 4B: the 1.7B thinks instead (it gave usable verdicts on the deck); say so.
- `CyberdeckApp._verdict_view`: 10-25: one tab per issue (up to 5), cheapest/likeliest first, each with its own test, parts and manual pages; the first tab is the summary with every part to order, the last the whole answer as written.
- `CyberdeckApp.act_verdict`: The deck's 4096-token models can't write 5 full issues.
- `CyberdeckApp.act_verdict`: Not enough data and no brainstorm yet: the plan may stop and ask for tests instead (the owner 11-13). After a brainstorm chat it diagnoses with what it has.
- `CyberdeckApp.act_verdict`: Blind first pass (config "verdict_blind_first", default on): pass 1 sees the evidence only, without the OPINION_FIELDS; pass 2 gets its ranking plus the opinions and says whether the evidence supports them.
- `CyberdeckApp.act_verdict`: The deck's own stop (no model): no brainstorm yet and the data check flags the codes or readings a diagnosis would rest on. The models diagnosed impossible data even when the prompt told them not to (sim v4).
- `CyberdeckApp.act_verdict.go.pass2_prompt`: Only the pages pass 1 used (the code procedures always): pass 2 re-read all of them before and took as long as pass 1. The source check still runs against every page (check_against=full).
- `CyberdeckApp.act_verdict.go`: 11-01: the thinking model writing the plan from scratch did worse than the plain one and looped on doubts. Now THINK HARDER = the plain model writes the plan, then the thinking model reviews it against the case and fixes only what the evidence says is wrong.
- `CyberdeckApp._verdict_done`: The deck's answer check sends the plan back once when issue 1 blames a part the case lists as verified good or the history says was just replaced (Qwen led with a just-replaced thermostat, sim v4)

### `app/ui/screens/parts.py`

- `CyberdeckApp._sop_view`: Typed, not a chip grid: no fixed repair list (and the 6-wide grid made the window wider than a 160%-scaled screen)

### `app/ui/screens/two_way.py`

- `CyberdeckApp.act_test_mode`: Keep the reference until the thread really ends (dropping a running QThread aborts the app); READ CAR comes back only once the port is closed.
