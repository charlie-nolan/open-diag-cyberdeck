# ADR-0007: Knowledge DB builders (kb/)

Status: Accepted (recorded 2026-11-20)

## Context

These decisions were written as code comments next to the code they explain. Comments are banned
(ADR-0001), so they are kept here. Each entry names the file and the function or class it applies to;
search the file for that name. When the code changes, update or remove the entry in the same change.

## Decisions

### `kb/add_nhtsa.py`

- Kb file name -> NHTSA MAKETXT values (Ram trucks live in dodge.db, as CHARM's "Dodge or Ram Truck" does)

### `kb/add_stackexchange.py`

- `match`: Short names (RAM, VW) count in a title only when not written in lower case ('ram air intake' isn't a Ram)
- `match`: A short make name alone (Ram, VW) needs one of its models named too.

### `kb/build_community.py`

- Forum dumps -> the make DB their threads go to (the record's own vehicle field says the exact model)
- `_stop`: Set by SIGTERM/SIGINT: finish the requests in flight, save them, start no new ones.
- ============================================================================ pass 0: prefilter Vocabulary that says a thread is about diagnosing/repairing a vehicle. Detection only: none of these words is tied to a cause (CLAUDE.md rule 1).
- Obvious non-diagnostic threads (dropped only when they also show no trouble code and no test)
- `step_extract`: Llama backend: our own llama-server already holds the GPU (gpu_guard counts it as busy), so only take the lock.
- ============================================================================ raw threads: every kept thread, searchable Step 2 of the community data (10-31): the LLM extraction reads only some threads, so every thread pass 0 kept also goes into kb/<make>.threads.db as plain text with FTS and vectors. No model reads them at build time and nothing is summarised: the app finds the threads and shows/quotes them with their link. A separate file so the make DB stays as it is and the deck can skip it.
- `step_rawembed`: One commit per chunk: Ctrl-C and rerun resumes.

### `kb/build_subaru_kb.py`

- `parse_fsm`: A CAPS heading (no section code) is a chapter only when the next structural heading is topic "1." -- topic numbering restarts in every chapter.
- `parse_fsm`: Topic numbering restarts at "1." in every chapter. When it restarts and no chapter heading was found above, the nearest CAPS heading since the previous topic names the new chapter.
- `split_long`: Paragraph fallback for blocks that are still huge.
- `step_diag`: FSM wording wins over RomRaider's; first row per code is kept.
- `step_charm`: Chassis is NULL for CHARM rows, so UNIQUE can't dedupe them; look up first.
- `step_charm`: Lead each page with its component and section ("Timing Belt > Labor Times"). Short labor/parts pages are often identical text for different parts, so the component must be in the hashed text, but not the category above it: Engine > Timing Belt and Maintenance > Timing Belt are the same page and should stay one row.
- `labor_from_sections`: Letters or a dash, or 6+ digits: GM's numbers are all digits (19115080) and were dropped before. Same rule as parts_sourcing/interchange.is_part_number.
- `labor_from_sections`: On parts pages (or any row with a part number) a bare decimal is a list price, not hours.
- `step_embed`: Keep existing vectors: drop ones whose row is gone (a reloaded manual), embed only new rows.
- `step_embed`: One transaction per chunk (~16k rows): a crash or Ctrl-C loses at most one chunk, and --missing resumes.
- `step_relink`: Keyed by content, so the same page under many years is parsed once.

### `kb/build_telemetry.py`

- GM brands: their PCMs speak GM mode $22 (whether a given PCM is a PCMHammer one shows in its replies)
- `parse_values`: '(–450 mmHg, –17.72 inHg)' after a kPa value is the same value in other units: one number is enough.
- `parse_values`: A typo on the page ('650-75'): no zone, never a guess.
- ---- conditions: only phrases a Python check can follow. Thresholds the manual doesn't give are generic and marked so (warm = coolant at least 80 °C as in app/live_data.py; stated rpm = ±10 %).
- ---- name -> canonical key: definition names first (the make's own protocol), then wording synonyms. Synonyms only translate wording into the definitions' terms (CLAUDE.md rule 1).
- `zone_rows`: Value cells take the header's condition columns in order, only when the counts agree (merged cells shift column numbers, so the index alone can't be trusted)
- `step_zones`: '(Except U5 model)': which cars isn't known here.

### `kb/car_db.py`

- `cmd_community_select`: The extraction's own filters (build_community.thread_filter), so the budget counts what would really run.
- `cmd_telemetry`: Zones quote their row, so a zone whose page isn't in this DB keeps the quote with no page id.
- `cmd_trim`: Knowledge: rows with no model are make-wide and stay; others need this model and an overlapping year range.
- `cmd_vision`: Codes whose procedure the manual already gives as text steps: their pictures are copies or wiring.

### `kb/charm_images.py`

- `kind_of`: No telling heading: under a testing/diagnosis heading, a tall narrow picture is usually a flowchart.

### `kb/convert_big_manuals.py`

- Marker_single, but empty images (0 px) are skipped and logged instead of crashing save_output ("cannot write empty image as JPEG"), which used to fail the whole chunk.

### `kb/embedder.py`

- `QueryEmbedder`: Qwen3-Embedding wants a one-line task description in front of the query (documents get none). It describes the task only; it says nothing about which causes or parts are likely.
- `QueryEmbedder._load_locked`: Transformers 5 loads the checkpoint's bfloat16 by default; on a CPU that is ~3x slower than float32 (537 vs 166 ms per query on the 5900X, 4 threads) for the same vector (cosine 0.9998). (.to() rather than a load kwarg: the deck's transformers may be older and not take dtype=.)
- `DocEncoder.__init__`: No bf16/fp16 matmul units on these CPUs: half precision is slower there.
- `DocEncoder.__init__`: Another job holds the GPU (often Ollama answering the picture server): same rule as at batch 1.
- `DocEncoder._forward`: Half precision overflowed on this batch (never seen on manual text): redo it in float32.
- `DocEncoder._encode_chunk`: The other GPU job (e.g. Ollama for a picture) has usually gone by now: grow back slowly.

### `kb/knowledge_load.py`

- `write_kind`: Update rows that exist (IS, not =, so a blank model or year still matches), add the rest.

### `kb/ocr_bench.py`

- `main`: With no text layer and no tesseract there is nothing to check against.

### `kb/pdf_to_md.py`

- The manuals whose marker conversion damaged the diagnostic charts (found 2026-10-19).
- Two-column manuals whose step charts print CHECK YES NO as pictures (2026-10-21).
- The 1999-2001 Subaru FSM step-chart icons: the CHECK YES NO marks in front of a step's question and its two answers are small pictures, so the text layer has only ': ...'. Matched by image digest (first 8 hex digits), never by xref: 1999 puts YES and NO inline, with no xref.
- `ruled_table`: A gap inside one cell (an indented line) makes a column no word starts in: merge it into its left neighbour.

### `kb/ship_images.py`

- `shrink`: Manual figures are line art; colour only adds bytes.

### `kb/tests/test_obd_all.py`

- `bitmap`: Python-obd is a deck dependency (requirements.txt), not needed for the KB tests.
- `Cars.test_slow_search_then_protocol_reused`: Longer than python-obd's old 2 s timeout.
